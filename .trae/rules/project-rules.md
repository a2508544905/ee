# 项目规则

本项目是「阶梯电价计算与查询系统」。以下规则对所有代码修改、新增、审查均强制生效。

## 技术栈

- 使用 **Python 3.11**
- GUI 使用 **tkinter**（Python 自带，禁止替换为 PyQt/PySide 等其他 GUI 库）
- 图表使用 **matplotlib**
- 数据导入导出使用 **openpyxl**

## 代码风格

- **所有函数必须有中文注释**（docstring 或行内说明，说明用途与关键逻辑）
- 变量和函数使用 **snake_case** 命名
- 命名应见名知意，避免单字母变量和无意义缩写
- 函数体建议不超过 30 行，超长应拆分

## 依赖管理

- **不得擅自新增依赖**
- 如需增加依赖，必须先说明原因并征得确认
- 所有依赖须写入 `requirements.txt`，并写明版本号

## 安全与配置

- **禁止在代码中硬编码文件路径和密钥**
- 文件路径、密钥、token 等敏感信息必须通过配置读取或环境变量注入
- 配置类数据（如电价档位规则）应放在 `config/`，由代码动态读取，不得写死在源码中

## 目录与分层

- 业务逻辑放在 `lib/`，界面代码放在 `ui/`，二者严格分层
- `ui/` 可调用 `lib/`，`lib/` 不得反向依赖界面，也不得引入 tkinter
- 入口文件只负责启动，不承载业务逻辑

## 自动维护

- 当用户说「增加规则」或「修改规则」时，先分析需要什么规则，然后直接修改本 Rules 文件，无需再逐条确认
- 若用户未指明具体规则内容，则基于项目现状与惯例，给出合理建议并直接写入

## 错误处理与数据校验

- 所有文件读写操作必须包含 try-except，捕获异常时必须给出中文错误提示
- 对用户输入先校验再使用，非法输入（空、非数字、负数、过大等）必须给出明确中文提示
- CSV 导入遇到错误行必须跳过并记录错误，而不是让程序崩溃；导入结束给出汇总（成功 X 条，跳过 Y 条）

## 日志安全

- 日志中不得记录密码、API Key、token 等敏感信息
- 日志文件 app.log 不提交到版本库（加入 .gitignore）

## 目录维护

- 新增文件后必须更新所在目录的 README.md
- 每个非空目录应有 README.md 索引说明

## 类型提示与正确性

- 核心函数（计算、导入、导出、统计、保存加载）必须添加类型提示（Type Hints）
- 实现功能前先定义「怎样算对」（期望值 / 边界），再编码实现并核对

## check 命令

- 修改代码后必须运行检查命令验证：
  `python -m pytest tests/ -v && python check_rules/run_all.py`
- 提交前确保所有测试通过、AST 规则无违规
