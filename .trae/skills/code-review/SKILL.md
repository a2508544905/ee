# 代码审查

本 Skill 用于审查 Python 代码质量，按固定步骤检查，最后汇总问题与修改建议。

## 适用场景

- 用户要求"代码审查"、"检查代码质量"、"帮我 review 代码"
- 提交或合并代码前对改动做质量把关

## 检查步骤

按以下顺序逐项检查，检查对象为指定的目标文件或目录下的所有 `.py` 文件。

### 1. 检查每个函数是否有中文注释

- 每个函数应有清晰的中文注释（docstring 或行内注释）
- 记录缺失注释的函数名和位置

### 2. 检查是否有超过 30 行的函数

- 函数体行数超过 30 行记为超长函数
- 记录函数名、所在文件、行数、起止行

### 3. 检查变量命名是否清晰

- 变量名应能见名知意（不用单字母、无意义缩写）
- 不符合规范的列出变量名和位置

### 4. 检查是否有多余的 import

- 未被使用的 import 记为多余 import
- 重复导入同一模块的 import 也计入
- 列出文件名、导出的模块、建议处理方式

## 输出格式

检查完成后，按以下格式输出结果：

```
## 代码审查报告：<目标文件或目录>

### 一、中文注释
- ✅ <通过项>
- ❌ <问题文件:行号> 函数 <名称> 缺少中文注释

### 二、超长函数（>30 行）
- ❌ <文件>:<起止行> 函数 <名称> 共 <N> 行

### 三、变量命名
- ✅ 命名清晰
- ❌ <文件>:<行号> 变量 <名称> 命名不清晰，建议改为 <建议名>

### 四、多余的 import
- ❌ <文件>:<行号> import <模块> 未使用，建议移除

### 修改建议
- 总结上述问题，给出具体、可执行的修改建议
```

若某类检查全部通过，统一写 `✅ 全部通过`。

## 注意事项

- 所有输出使用中文
- 不修改目标代码本身，只输出审查报告
- 举例用通用占位符，不包含具体项目私密数据
