# 代码重构

本 Skill 用于对 Python 项目执行**安全、逐步、可回滚**的重构。核心原则：不改变行为，只改进结构；每步小改、每步验证。

## 适用场景

- 用户要求"代码重构"、"优化代码结构"、"整理代码"
- 项目存在超长函数、命名不规范、目录混乱等问题需要整理

## 重构前准备

1. 先确认程序当前能正常运行：运行测试（若有）`python -m unittest discover -s tests -p "test_*.py"` 或手动启动验证
2. 记录当前测试通过状态，作为重构后的回归基线

## 重构遵循的规范

### 目录规范

- `config/`：放配置文件（档位、阈值、名单等）
- `lib/`：放核心业务逻辑（不依赖界面，不引入 tkinter）
- `ui/`：放 tkinter 界面代码
- `data/`：放数据文件（CSV、JSON、数据库）
- `tests/`：放单元测试
- 依赖方向单向：`ui/ → lib/ → config+data`

### 函数规范

- 单一职责：一个函数只做一件事，函数体建议不超过 30 行
- 函数名以动词开头（如 `calculate_*`、`load_*`、`save_*`、`export_*`）
- 每个函数必须有中文注释（docstring 或行内注释）

### 命名规范

- 变量、函数用 `snake_case`（全小写下划线分隔）
- 常量用全大写 + 下划线（如 `MAX_USAGE`）
- 命名见名知意，避免单字母变量和无意义缩写

## 重构执行步骤

严格按以下顺序，**每步只改一组相关代码，改完立即验证**：

1. **先分析**：阅读目标文件，列出问题清单（超长函数、不规范命名、错误的目录归属、多余的 import 等）
2. **找出问题**：按规范逐项核对，定位具体文件与行号
3. **逐个修改**：一次只处理一个问题，不要一把梭
4. **每步验证**：每移动/修改一组文件后，运行测试确认功能正常（`python -m unittest discover -s tests -p "test_*.py"`），再继续下一步

## 典型重构动作

- **拆分过长的函数**：把超 30 行的函数按职责拆成多个小函数，各自带中文注释
- **修正不规范的命名**：把单字母/无意义缩写改成语义清晰的 snake_case 名，并同步更新所有引用
- **更新 import 路径**：文件移动后修正 import，保持依赖方向单向
- **移动文件到正确目录**：把放错位置的文件移到规范目录，并更新 import 与引用

## 输出格式

重构过程中，按需输出进度：

```
## 重构分析：<目标文件或目录>
- 问题：<已发现的问题列表，附文件:行号>
- 优先级：<按影响大小排序>

## 重构进度
- [x] 步骤1：<做了什么>（验证：<测试结果>）
- [ ] 步骤2：<将做什么>
- [ ] ...
```

## 注意事项

- 重构**不改变程序行为**：计算结果、界面布局、数据格式必须保持一致
- 每步验证通过后再提交，避免一次大改引入难排查的回归
- 所有输出使用中文
